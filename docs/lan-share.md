# 局域网会话分享

> 状态：第一版已完成（2026-11-16）。Linux 本机实测过对话、文件、终端、内置浏览器；Windows、macOS 还没实测。
> 公网分享（第 9 节，2026-11-20）：经自己的服务器（SSH 反向转发），用 ssh2 搭的测试服务器测过，没在真的云服务器上测过。

把一个会话分享给同一局域网里的人。对方用自己的浏览器打开分享链接，进的是**同一个会话**，可以接着对话，会话里能做的和本机一样；右侧面板有文件、终端、内置浏览器。

## 1. 范围

| 项 | 访客看到的 |
| --- | --- |
| 对话 | 被分享的这一个会话，和本机实时同步：发消息、中断、排队、权限确认、切模型和推理强度、权限模式、目标、压缩、清空、附件、注释、后台任务 |
| 输入框上面 | 什么都不放（没有技能、插件、浏览器、Computer Use）；输入框里的 `@`、`/` 照常能用 |
| 右侧面板 | 文件、终端、内置浏览器（分享方桌面版里这个会话的标签页） |
| 没有的 | 侧栏、其他会话、设置页、删除和重命名会话、分叉 |
| 工具 | 会话照常挂所有工具（Computer Use、外部浏览器、终端……），分享不改会话本身 |

## 2. 总体结构

原来的网关监听（`127.0.0.1:8788`）、Vite（`localhost:5180`）、`API_TOKEN` 鉴权钩子、事件流都没改。局域网的访问另走一个入口，只在有分享时才监听。

```
访客的浏览器 ──http://<本机局域网 IP>:8789──▶ 网关的局域网入口（share/lan-server.ts，有分享时才监听 0.0.0.0:8789）
                                              │ 校验分享令牌、只放行这个会话用到的接口
                                              ├─ /api/*  ──转发──▶ 网关 127.0.0.1:8788（原样）
                                              └─ 其他    ──转发──▶ Vite localhost:5180（页面、HMR）
本机的桌面版、网页：照旧直连 5180 / 8788，不经过这个入口
```

- **为什么另开入口**：Vite 改成监听局域网的话，局域网请求经它的代理到网关时都是 127.0.0.1，网关分不清本机和访客；没分享时 5180 也对局域网开着。另开入口时，进来的请求一律是访客，原来的逻辑一行不用动。
- **页面**：开发时转发给 Vite（`SHARE_CLIENT_URL`，默认 `http://localhost:5180`），和本机是同一份代码，改了代码访客那边也热更新。转发时 `Host`、`Origin` 换成 Vite 自己的（Vite 8 只认本机的 Host）。以后打包桌面版时，入口改成直接发 `client/dist`。
- 没带令牌打开 `/`、`/index.html` 时返回一句提示（否则会加载成本机的界面，接口全是 401）；Vite 的 HMR 也连 `/`（WebSocket），放过去。

## 3. 分享的管理（网关）

- **存储**（`share/store.ts`）：`$CLAUDE_CONFIG_DIR/gateway-shares.json`（600），每条 `{ sessionId, token, createdAt, lan, public }`，一个会话最多一条，令牌是 24 字节随机数的 base64url。`lan`、`public` 是分享到局域网、公网（第 9 节），两种共用一个令牌，都停了才删掉这条；加公网分享之前的记录没有这两项，读的时候当成只分享到局域网。网关重启后照旧有效，启动时有分享就开始监听入口。
- **接口**（`http/routes/shares.ts`，给本机用，局域网入口不放行）：
  - `GET /shares`：所有分享，加上入口端口、本机的 IPv4 地址（`os.networkInterfaces()`，去掉回环和 169.254.x.x）和公网隧道的状态
  - `POST /sessions/:id/share`：开分享，已有就用原来的。入口没能监听（端口被占用）时撤掉这次新开的、报 500
  - `DELETE /sessions/:id/share`：停止局域网分享（还分享到公网时只去掉 `lan`）
  - `POST`、`DELETE /sessions/:id/share/public`：开、停公网分享，见第 9 节
- **入口的开关**（`LanServer.sync()`）：有分享时监听 `0.0.0.0:<SHARE_PORT>`（默认 8789），最后一条停掉时关闭；停掉的分享的连接（事件流、终端、浏览器）立刻断开。
- **会话删除时**删掉它的分享；**会话清空后**（Claude Code 换了新的会话 id）分享跟到新 id，令牌不变（`routes/sessions.ts` 的 delete、clear 里各一行）。

## 4. 局域网入口（`share/lan-server.ts`）

独立的 `http.Server`，自己转发 HTTP 和 WebSocket 升级请求。

- **令牌**：页面地址 `/share/<令牌>`；之后的请求带 `X-Share-Token` 请求头，EventSource、WebSocket、`<img>` 用 `?share=<令牌>`。对不上 → 401。转给网关时令牌放在 `X-Share-Token` 里（`/share/info`、`/share/browser` 据此认出是哪个分享），网关设了 `API_TOKEN` 时补上 `Authorization`。
- **放行的接口**（`allowed()`，`/api` 后面的路径；`:id` 必须是这个分享的会话），其余 403：

| 用途 | 接口 |
| --- | --- |
| 分享本身 | `GET /share/info`（会话 id、工作目录、标题、是不是普通会话）、`/share/browser`（WebSocket，第 6 节） |
| 会话 | `GET /sessions/:id`，`/sessions/:id/` 下除了 `fork`、`share`、`share/public` 的所有接口（不能 PATCH 重命名、DELETE 删除） |
| 输入框要的 | `GET /config`、`/models`、`/capabilities`、`/external/tabs`（消息里 `@Chrome` 之类的名字和图标）、`/health`，`POST /uploads` |
| 右侧面板 | `/files*`、`/terminals*` |

  网页预览（`/files/page/…`）网关本身就不要求令牌，入口也直接放行。
- **转发**：事件流不缓冲；上游断了访客这边也断开（同 `client/vite.config.ts` 的处理），访客关掉页面时取消上游的请求。

## 5. 访客的网页

- **入口**（`client/src/main.tsx`）：地址是 `/share/<令牌>` 时设上分享令牌（`api.ts` 的 `setShareToken`），渲染 `ShareApp`；否则照旧渲染 `App`。
- **http 打开时缺的接口**（`client/src/insecure-context.ts`，入口最先加载）：访客用 `http://<局域网 IP>` 打开，不是安全来源，浏览器不给 `crypto.randomUUID`（界面到处用它生成 id，没有时页面一加载就出错、一片空白）和 `navigator.clipboard`。没有时补上：前者用 `crypto.getRandomValues` 拼，后者只能写文字（`execCommand("copy")`），复制图片不行。本机是 localhost，本来就有，走不到这里。只用 127.0.0.1 测发现不了，要用局域网 IP 打开测。
- **请求**（`api.ts`）：有分享令牌时请求都带上（`authHeaders()`、`withToken()`、事件流）。本机不设，和原来完全一样。
- **`ShareApp`**：每 5 秒问一次 `/share/info`。会话清空换了 id 就换到新会话；401 或连续 3 次连不上（最后一个分享停掉时入口不再监听，约 15 秒）显示「分享已结束」。对话是本机同一个 `Chat`，传 `guest`：输入框上面不放按钮、没有分叉。没有侧栏、设置。
- **右侧面板**：同一个 `SidePanel`。文件的上传下载走 HTTP（访客不是桌面版，本来就走这条）；终端按会话列、按会话建（接口本来就支持）；回复里的文件链接、网址照本机打开在面板里。

## 6. 内置浏览器

本机面板里的网页是外壳的原生视图；访客那边没有外壳，改成外壳推画面、访客的操作发回来。

```
访客：RemoteBrowserTab（<img>）── RemoteBrowser（WebSocket /api/share/browser）──▶ 局域网入口 ──▶ 网关 ShareBrowserRelay
   ──原有的 /browser/host WebSocket（share 开头的消息）──▶ 外壳 GatewayBridge ──▶ ShareStream（desktop/src/browser/share-stream.ts）──▶ BrowserViews
```

- **访客页面**（`client/src/state/remoteBrowser.ts`）：`RemoteBrowser` 实现和桌面版一样的 `DesktopBrowserApi`，`ShareApp` 经 `RemoteBrowserContext` 交给面板。`SidePanel` 在没有桌面版、有它时用它，标签页逻辑（补标签页、切换、新标签页的地址栏）照用；标签页内容换成 `RemoteBrowserTab`。本机的界面没有这个 context，走原来的 `BrowserTab`。
- **网关**（`share/browser-relay.ts`）：按访客记着看哪个会话、看哪些标签页的画面；同一个会话、同一个标签页几个人看，外壳那边只推一份。对标签页的操作只认这个会话的标签页（外壳推来的列表里有的）。外壳断开、重连时告诉访客，重连后重新要列表和画面。`BrowserHost` 多了 `onShare` / `postShare`，外壳发来的 share 开头的消息交给它。
- **外壳**（`share-stream.ts`）：
  - 列表：有访客看的会话，标签页一变就推（50ms 合并）；AI 切标签页（`activate`）也推。
  - 画面：有访客看的标签页接连 `capturePage`（约每秒 10 帧），宽于 1600 像素的缩小，JPEG 质量 70，和上一帧一样不发，发给网关的积压超过 2MB 时跳过这一帧。不在主窗口显示的标签页用 `stayHidden` 截，截图期间照常渲染（同 `views.ts` 的 `whileRendering`），本机没在看的标签页也有画面。
  - 输入：经标签页的调试接口注入（`Input.dispatchMouseEvent`、`Input.dispatchKeyEvent`、`Input.insertText`，同 AI 的 Playwright），网页不在前台、窗口没有焦点也收得到。网页收到的输入算「用户」的（`input-event`），告诉模型时和本机用户一样。
  - 鼠标指针形状（`cursor-changed`）推给访客。
  - 新建、关闭、跳转、前进后退、地址栏建议用 `BrowserViews` 原有的方法。
- **`RemoteBrowserTab`**：画面按比例缩放居中，鼠标坐标按比例换回网页的 CSS 像素；左键、中键、移动（每 33ms 最多一次）、滚轮转发，右键不转发（菜单会弹在分享方的屏幕上）。键盘接在一个看不见的输入框里：按键阻止默认、整个发过去（可打印字符带 `text`）；输入法组字结束（`compositionend`）、粘贴、没经过按键的输入（手机软键盘）整段用 `insertText` 送。
- **画面尺寸**：访客在前面看着的标签页，把画面区域的大小（CSS 像素，大小变了停 200ms 再报）发给外壳（`shareResize`）。本机没在显示这个标签页时（停放着），网页按访客的大小排版，画面铺满（`views.ts` 的 `fitParked`，停放窗口比它小就放大；截图循环里每轮再对一次，本机在面板里看过、又收回停放窗口后改回访客的）；本机正显示着时按本机面板的大小，访客那边按比例缩放、留边。几个访客看同一个标签页按最后报的；访客不看了网页保持最后的大小，本机在面板里打开时变回本机的。
- **前提**：分享方的桌面版开着；没开时访客的浏览器标签页显示「分享方的桌面版没有打开」。
- **没做的**：网页弹的选择文件对话框、alert（弹在分享方屏幕上）、剪贴板从网页复制到访客这边、选择元素和网页标注、下载列表（下载照旧存进会话的工作目录，访客在文件树里能看到、能下载）。

## 7. 本机的界面

- 侧栏会话的「…」/ 右键菜单（`Sidebar.tsx`）在「重命名」「删除」之间：没分享时「分享到局域网」（开分享、复制第一个地址的链接），分享中是每个地址一条「复制分享链接」和「停止分享」。
- 分享中的会话标题后面有个分享图标。分享列表（`state/shares.ts`）和会话列表一起每 10 秒刷新。
- 复制、出错的提示浮在窗口底部，几秒后消失；复制不了（没有剪贴板权限）时直接显示链接。
- 链接：`http://<地址>:<SHARE_PORT>/share/<令牌>`。地址列出本机所有 IPv4 网卡（包括 Docker 的网桥、公网地址），选局域网里对方连得到的那个。

## 8. 对现有逻辑的影响

没有开分享时，网关不多监听任何端口，代码路径和原来一样。改到原有代码的地方：

1. 删除会话时一起删掉它的分享；清空会话时分享跟到新 id（`routes/sessions.ts`）。
2. 访客开的标签页、终端，本机面板里也会出现（属于同一个会话）；访客在内置浏览器里的操作告诉模型时记成「用户」。
3. 侧栏菜单多了分享的项，分享中的会话多一个图标；主页刷新会话列表时多取一次 `/shares`。
4. 有访客看内置浏览器时外壳多做截图，多占些 CPU；没人看时不做。外壳和网关之间多了 share 开头的几种消息，旧版本的一边收到会忽略。
   访客看着本机没在显示的标签页时，网页按访客面板的大小排版（AI 在这个标签页上截图、操作也是这个大小，原来停放着的是 1280×800），停放窗口可能被放大。
5. 第一次开分享时，Windows 会问是否允许 Node.js 访问网络，要点允许；macOS 可能也会提示。
6. 分享存在文件里，网关重启后仍然有效。
7. `Chat` 导出了，多一个 `guest` 属性；`SidePanel` 多读一个 context；`BrowserTab.tsx` 导出了 `loadErrorText`、`displayUrl`；`api.ts` 的请求头统一由 `authHeaders()` 生成（本机没有分享令牌时内容和原来一样）；`views.ts` 多了只读的 `isShown()` 和 `fitParked()`；`BrowserHost` 多了 `onShare` / `postShare`。
8. 公网分享（第 9 节）带来的：设置页多一节「公网分享」；`ssh/host.ts` 导出了 `connectOptions`、`SshHost` 多了只读的 `sessionPassword`；`DELETE /sessions/:id/share` 只停局域网分享（没分享到公网时和原来一样删掉整条）；两种都分享着时局域网那项叫「停止局域网分享」；没配置服务器时菜单和原来一样，配置了多一项「分享到公网」。

## 9. 公网分享（自己的服务器）

侧栏菜单里「分享到局域网」下面是「分享到公网」：同一个会话、同一个访客页面，只是经自己服务器的公网地址打开。服务器在设置页「公网分享」里配置：选「SSH 连接」里的连接，或者手动填；**没配置时菜单里没有「分享到公网」**。

```
访客 ──http://<服务器>:<公网端口>──▶ 服务器的 sshd ══SSH 反向转发══▶ 网关
                                                                     ▼
                     公网分享的本机入口（127.0.0.1:8790，有公网分享时才监听，和局域网入口同一套转发，第 4 节）
```

### 9.1 入口和分享记录

- `LanServer` 多一个只监听 `127.0.0.1:<SHARE_TUNNEL_PORT>`（默认 8790）的入口，有 `public` 的分享时才监听，转发规则和局域网入口一样。两个入口各认各的：经公网入口进来的只认 `public` 的分享，经局域网入口进来的只认 `lan` 的。所以只分享到公网时 8789 不对局域网开；只分享到局域网的链接换成公网地址打不开。
- 两个入口都对 `/.well-known/claude-app-share` 直接回这个网关进程的随机标识（自检用，9.4）。
- 到服务器的转发（`share/ssh-tunnel.ts`）：有公网分享时连上，最后一个公网分享停掉、网关退出时断开。设置改了时断开现在的，还有公网分享就按新设置重新连（公网地址可能变，之前发出去的链接跟着失效）。

### 9.2 接口和菜单

- `GET /shares` 多了 `publicEnabled`（配置了服务器）和 `tunnel`（转发的状态、公网地址）。
- `POST /sessions/:id/share/public` 开分享、开入口、连服务器，等到自检通过（最多 25 秒），返回 `SharesView`（`tunnel.url` 是公网地址）；没配置服务器时 400；连不上、自检不通时撤掉这次新开的分享、报 500（错误信息原样显示在侧栏底部的提示里）。`DELETE` 停掉。
- 菜单：配置了服务器、没分享到公网时「分享到公网」，分享中是「复制公网链接」和「停止公网分享」（没配置但还有公网分享的记录时也显示这两项，能停掉）。两种都分享着时，局域网那项叫「停止局域网分享」。复制公网链接时转发没连着会重新连。
- 访客页面：停掉公网分享后服务器上的端口也关了，访客连不上，同局域网分享连续 3 次连不上算分享结束。
- 前提：同局域网分享，本机的网关和页面服务（开发时是 Vite）要开着。

### 9.3 访客的页面：打包版、压缩（`share/client-bundle.ts`）

开发时访客的页面由 Vite 开发服务器发：开发版代码不压缩混淆、没有 gzip、每个模块一个请求，第一次打开约 100 个请求、7.8MB（开发版 React 一个就 3MB）。局域网里不显眼，经服务器、SSH 转一圈的公网很慢（实测约 300KB/s，要二十几秒）。所以**公网入口**（局域网入口不变，照旧是 Vite、有热更新）：

- **打包版**：网关用 `vite build` 打一份放在 `gateway/.data/share-client`（`SHARE_CLIENT_DIST`），首屏 3 个请求、约 1.4MB，压缩后约 410KB；mermaid、代码高亮等用到时才加载。
  - 什么时候打：开公网分享时、网关启动时有公网分享、访客打开页面时（最多 5 秒查一次），源码（`client/src`、`client/public`、`index.html`、`vite.config.ts`、`package.json`、`gateway/src/shared`）里最新的修改时间比打包时记下的（`.built-from`）新就在后台重新打，同时只打一个，约 5–15 秒。
  - 先打到 `share-client.tmp`，新的 assets 拷进去（旧的留 7 天，已经打开着的页面还会按需加载旧文件），再换掉 `index.html` 等。
  - 重新打包期间先发上一次打的；一次都还没打好、打包失败时照旧转给 Vite（访客照样能用，只是慢）。
  - 访客看不到代码的热更新：改了网页代码，下次打开页面时才是新的。
- **发文件**：`/assets/` 下有的总是发（`cache-control: public, max-age=31536000, immutable`，文件名带哈希）；其他路径有打包好的就发（`no-cache` + ETag，没改回 304），访客页面的地址 `/share/…` 发 `index.html`；没有的（打包期间从 Vite 打开的页面要的 `/src/…`、`/@vite/…`）照旧转给 Vite。
- **压缩**：文本类内容（网页、接口的 JSON、打包期间转给 Vite 的模块）按浏览器支持用 brotli 或 gzip；打包版的文件压一次留在内存里（brotli 9 档），转发的边转边压（brotli 5 档）。事件流（`text/event-stream`）不压（会憋着不发），图片、内置浏览器的画面（JPEG）本来就压过。实测接口的 JSON 191KB → 6KB。

### 9.4 服务器的转发（`share/ssh-tunnel.ts`）

- **设置**（`share/share-settings.ts`，设置页「公网分享」）：
  - 「SSH 连接」：选设置「SSH 连接」里的连接（设置页添加的、`~/.ssh/config` 里的都行），或者「手动填写」。
  - 手动填写时：服务器地址、SSH 端口、用户名、密码、私钥文件（选填，可以写 `~/`）。
  - 选了连接时只有密码（选填，连接要密码登录时用）。
  - 公网端口（默认 8790）、链接里的地址（选填，有域名时填）。
  - 选「手动填写」、地址和用户名都清空后保存是不用公网分享：密码一起清掉，现有的公网分享全部停掉。选的连接在「SSH 连接」里删掉了也当没配置。存在 `$CLAUDE_CONFIG_DIR/gateway-share.json`（600），**密码也存**（断线、网关重启后要自己重连；「SSH 连接」那边的密码只在内存里，不一样），不回给网页，同网络代理的密码。接口 `GET`、`PUT /share/settings`。
- **连接**：网关用 ssh2 单独开一条连接（不走「SSH 连接」那条会部署 Claude Code 的，那条连没连着都不影响），认证依次试私钥文件、ssh-agent、密码（密码登录和键盘交互）。
  - 选了「SSH 连接」里的连接时：地址、账号、密钥、ProxyJump / ProxyCommand 都按那个连接解析（`ssh -G`，同 `SshHost`，用的是 `ssh/host.ts` 导出的 `connectOptions`）；密码先用「公网分享」里填的，没填用这次在「SSH 连接」里输入过的（只在内存里，`SshHost.sessionPassword`）。在服务器上 `forwardIn("0.0.0.0", 公网端口)`（同 `ssh -R 0.0.0.0:端口:127.0.0.1:8790`），进来的连接接到本机入口。SSH 心跳 15 秒一次，连续 3 次没回就当断了。
- **主机密钥**：
  - 手动填写的：第一次连上时记下指纹（不弹确认），之后服务器的密钥和记下的不一样就不连、报出两个指纹；设置页「重新记录」或者改了地址、SSH 端口时忘掉记下的。
  - 选的连接：要是「SSH 连接」里信任过的，或者本机 known_hosts 里记着的；都没有时报错，让先在「SSH 连接」里连一次确认指纹。
- **自检**：开了端口后，网关从外面访问一次 `http://<链接里的地址>:<公网端口>/.well-known/claude-app-share`，回的是这个网关的标识才算连上。sshd 默认 `GatewayPorts no`，端口只开在服务器自己的 127.0.0.1 上，外网打不开；没放行防火墙、安全组也一样——这时报错里写明要检查这几项，不会显示成功。
- **外面打不开时的诊断**：自检连不上时，趁还登录着服务器跑一段 sh（`ss -ltn` / `netstat -ltn` 看这个端口监听在哪些地址，grep sshd 配置里的 `GatewayPorts`）：
  - 只开在 127.0.0.1 / ::1 上（或者看不到监听、配置里没开）：报「GatewayPorts 没开」，状态带 `fix: "gatewayPorts"`，设置页显示一键开启的按钮。
  - 已经在所有地址上监听：报「多半是防火墙或安全组没放行」。
- **一键开启 GatewayPorts**（`POST /share/settings/fix-gateway-ports`，设置页的「开启」按钮，只在上面那种情况显示，点了才改）：用设置页填的配置登录服务器，执行一段 sh：
  1. 不是 root 时要 `sudo -n` 能免密，否则不改（`nosudo`）。
  2. `/etc/ssh/sshd_config` 里要有 `Include /etc/ssh/sshd_config.d/*.conf`，否则不改（`noinclude`，免得把一行写进 `Match` 段里）。
  3. 写 `/etc/ssh/sshd_config.d/99-claude-app.conf`（`GatewayPorts clientspecified`）。
  4. `sshd -t` 检查不过就删掉这个文件、不重启（`badconfig`）；`sshd -T` 看生效的值不是 clientspecified / yes（别处先写了）也删掉（`overridden`）。
  5. 重启 sshd：`systemctl restart ssh`（或 sshd）→ `service ssh restart` → 给 `/run/sshd.pid` 里的监听进程发 HUP（sshd 收到 HUP 重新读配置），前一种不行才试后一种；已经连着的 SSH 都不断。
  - 配置里已经写了、端口还是只开在 127.0.0.1 上（改了没重启）：诊断报「还没生效，要重启 sshd」，按钮照样显示，点了会重新走一遍（写的是同一个文件）。
  - 自动改不了时报原因，附上手动执行的命令。成功后有公网分享时断开现在的转发重新连（GatewayPorts 只对新连接生效），等连好才返回；设置页接着测一次（这时用的就是重新连好的转发）。
  - 安全组在云服务器的控制台里，改不了。Windows 服务器不支持。
- **断线**：连上过又断了（网络断、服务器重启）就按 2、5、10、30、60 秒退避重连，一直重试到没有公网分享；一次都没连上（密码不对、自检不通）不重试，等下次点「分享到公网」。
- **端口开不了**（`Unable to bind`）：多半是一会儿就好的占用——断线重连时服务器还没发现上一条连接断了、端口还挂在它上面，或者测试连接刚好占着。断开、2 秒后重新连，最多再试 4 次，期间状态一直是 starting；还不行才报错（断线重连中的照样按退避继续）。
- **测试连接**（`POST /share/settings/test`）：按设置页填的（还没保存的）配置连一次、开端口、自检，然后断开。本机入口可能没在监听，进来的连接接到一个只回自检的临时服务上。
  - 填的和保存的一样、又有公网分享（或者转发连着）时不另开一条（会和公网分享抢同一个端口），直接用公网分享的转发：没连着就连，回的是它的结果，设置页「当前」跟着刷新。
- **链接**：`http://<链接里的地址>:<公网端口>/share/<令牌>`；链接里的地址自己带了端口（服务器上经 nginx 等转过的）就不再拼公网端口。是 http，同局域网分享靠 `insecure-context.ts` 补上缺的接口，复制图片不行；要 https 得在服务器上另配 nginx / Caddy。
- **服务器上要做的**：`/etc/ssh/sshd_config` 里 `GatewayPorts clientspecified`（或 `yes`）后重启 sshd；`AllowTcpForwarding` 不能是 `no`；防火墙、安全组放行公网端口。
